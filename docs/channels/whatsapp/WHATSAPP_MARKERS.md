# Специфікація маркування та Reconcile-алгоритму каналу WhatsApp (SvitloSk)

## 1. Призначення

Канал **SvitloSk** у WhatsApp (`0029Vb96XUUIN9ixA88Umz3Y`) працює за принципом **Declarative State Reconciliation** ([`WhatsAppReconciler`](../../SvitloSk.Publisher.Infrastructure/Channels/WhatsApp/WhatsAppReconciler.cs)). На кожному циклі синхронізації паблішер зчитує фактичний стан хвоста каналу через Puppeteer-міст (`GET /tail-state`), порівнює його з очікуваним набором публікацій та виконує мінімально необхідні дії для підтримки ідеальної послідовності постів.

Усі пости, графічні банери та 12-підчерговий графік ГПВ генеруються для WhatsApp **повністю автономно** від Telegram-каналу ([`IngestWhatsAppEditorialInputAsync`](../../SvitloSk.Publisher.Infrastructure/Services/FeedIngestionService.cs)). Усі помилки та аудит-події записуються виключно в системні логи (`local/logs/publisher/sync.log` та `local/logs/whatsapp-bridge.log`).

## 2. Формат маркерів

Кожен пост у каналі WhatsApp містить у кінці тексту (останнім рядком після порожнього рядка) **звичайний текстовий маркер** без курсиву чи іншого форматування:

| Тип | Призначення | Формат маркера | Приклад |
| :---: | :--- | :--- | :--- |
| **`T`** | Сьогоднішні публікації за поточну добу (`Today`) | `T · дд.мм · NN` | `T · 26.10 · 00` |
| **`F`** | Прогноз на завтра (`Forecast`) | `F · дд.мм · NN` | `F · 27.10 · 01` |
| **`G`** | Графік погодинних відключень (12 підчерг, `Graphic`) | `G · дд.мм` | `G · 26.10` |
| **`S`** | Технічний статус моніторингу (завжди останній пост у каналі) | `S · дд.мм` | `S · 26.10` |

### Правила нумерації `NN`:
1. **`00`** — завжди заголовний банер блоку:
   - `T · дд.мм · 00` — ранковий заголовний банер журналу на сьогодні (`journal_header`) або банер «Знеструмлень не заплановано».
   - `F · дд.мм · 00` — заголовний банер прогнозу на завтра (`tomorrow_separator`).
2. **`01`** — пріоритетне місце для адміністративного центру (**м. Старокостянтинів**, `starokostiantyniv`), якщо для міста є активні відключення.
3. **`02 .. NN`** — старостинські округи громади у порядку черговості або першої появи протягом доби.
4. **Стабільність та самовідновлення (`Self-Healing`):** закріплений за територією номер `NN` зберігається у [`local/registry/whatsapp_post_journal.json`](../../SvitloSk.Publisher.Infrastructure/Channels/WhatsApp/WhatsAppPostJournalStore.cs) та додатково відновлюється напряму з DOM каналу за назвою території у першому рядку поста ([`WhatsAppContentFormatter.ResolveTerritoryIdFromPostText`](../../SvitloSk.Publisher.Infrastructure/Channels/WhatsApp/WhatsAppContentFormatter.cs)).

## 3. Алгоритм оновлення та перебудови хвоста (Варіант А)

Оскільки WhatsApp Web дозволяє редагувати повідомлення на місці (`Edit`) лише протягом **~15 хвилин** після публікації, [`WhatsAppReconciler`](../../SvitloSk.Publisher.Infrastructure/Channels/WhatsApp/WhatsAppReconciler.cs) застосовує двоступеневий алгоритм:

1. **Протягом вікна редагування (до 15 хв):** змінений пост оновлюється на місці (`UpdateTextMessageAsync` / `POST /edit`) без видалення сусідніх постів.
2. **Після закриття вікна редагування (`windowExpired`) — Варіант А:**
   - Якщо змінився пост території `T · дд.мм · NN` (де `NN >= 01`), пост прогнозу `F` або графік `G`, паблішер видаляє цей пост **і всі пости нижче нього** (`NN..K`, `F`, `G`, `S`) у зворотному порядку (знизу вгору) та публікує їх заново у суворій послідовності `01, 02, 03...`.
   - **Захист якірного банера `T · дд.мм · 00`:** якщо минуло 15 хвилин і оновився лише зведений перелік населених пунктів у шапці `T · 00`, банер `T · 00` **залишається на позиції #0** без видалення решти денних постів (виняток — перехід від стану «Без відключень» до появи реальних відключень).
3. **Видалення застарілого прогнозу `F`:** усі пости з маркером `F · дд.мм · NN`, де дата `<= сьогодні`, гарантовано видаляються **до** публікації чи оновлення будь-яких сьогоднішніх постів `T`.
4. **Єдиний статус `S` у хвості:** якщо у хвості каналу були додані або перепубліковані пости нижче `S`, старий `S` видаляється і створюється новий у самому кінці стрічки.

## 4. Межа доби (`KyivClock`)

Усі дати (`EditionDate`, перевірка застарілих прогнозів `F`, ротація журналу) обчислюються виключно за київським часом через [`KyivClock`](../../SvitloSk.Publisher.Core/Engine/KyivClock.cs) (`FLE Standard Time` / `Europe/Kyiv`). Публікація сьогоднішнього журналу `T` за дату `D` дозволена лише тоді, коли в Києві вже настала дата `D`.

## 5. Команди діагностики та керування

- **Перевірка доступності мосту та каналу:**
  ```powershell
  dotnet run --project SvitloSk.Publisher.Infrastructure -- --whatsapp-check
  ```
- **Зчитування поточного стану хвоста каналу напряму з мосту:**
  ```powershell
  Invoke-RestMethod -Uri "http://127.0.0.1:3000/tail-state" -Method Get
  ```
- **Автономний запуск синхронізації WhatsApp (Reconcile):**
  ```powershell
  dotnet run --project SvitloSk.Publisher.Infrastructure -- --whatsapp-sync
  ```
- **Тимчасове вимкнення Reconcile-режиму (повернення до legacy-пайплайну):**
  Встановити змінну середовища `WHATSAPP_RECONCILE_ENABLED=false`.
