# ADR-005: Situation Model Integration Blocked by Missing Runtime Orchestration

## Context
During Task P2-002, the objective was to integrate the `SituationModel` into the existing Publisher execution flow.
The constraint mandated reusing the existing orchestration and discovering where `InputPackage` first becomes available, specifically checking if a runtime loop exists.

## Analysis of Existing Architecture
1. **Runtime Loop**: There is no existing runtime loop. `SvitloSk.Publisher.Host/Program.cs` builds the generic host and calls `host.Run()`, but there are no `BackgroundService`, `IHostedService`, or polling timers registered to drive the application loop.
2. **InputPackage Availability**: The interface `IInputPackageProvider` with `GetLatest()` exists, but there is no implementation registered in DI, and it is never invoked anywhere in the codebase.
3. **Orchestration Entry Point**: `SynchronizationEngine` is registered as a Singleton, and its method `MaintainPublisherState()` is the theoretical orchestration point. However, it throws `NotImplementedException` and is never invoked by the Host.

## Missing Architectural Elements
The integration of `SituationModel` requires an active execution context. The following structural elements are missing and cannot be invented without violating constraints:
- A host-driven runtime loop (e.g., a background worker or chron-based trigger) to drive the Publisher pipeline.
- An implemented orchestration layer inside `SynchronizationEngine` to retrieve an `InputPackage` via `IInputPackageProvider` and pass it to the `SituationModel`.

## Decision
Integration cannot proceed. Task P2-002 is halted because there is no existing integration point or data flow for an `InputPackage`.
