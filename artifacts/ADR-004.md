# ADR-004: Situation Model Comparison Semantics Unspecified

## Context
Task P2-001 involves the implementation of the Situation Model (S-01 through S-17). The Situation Model relies on deterministic comparisons between an incoming `InputPackage` and the current `Publication` state (the baseline).

While the structural domain gaps have been resolved (via `EDITORIAL_DOMAIN_MODEL.md` internal representation properties), the exact engineering and mathematical semantics for executing these comparisons remain entirely unspecified. Implementing the Situation Model now would require inventing architectural rules.

## Missing Engineering Knowledge

The following critical algorithms are undefined in the canonical specification:

### 1. Address Equality Semantics (S-02, S-03, S-04)
The Situation Model must detect when a `TextInputPackage` contains changed, added, or removed addresses compared to the `Publication`. 
- **Missing Knowledge**: The definition of equality for the `Addresses` property. It is undefined whether the system must treat the collection as a strictly ordered array, an unordered set, or whether string normalization (trimming, casing, canonicalization) must be applied prior to comparison to prevent false positives.

### 2. Graphic Schedule Comparison (S-09)
The Situation Model must detect when the `GraphicInputPackage` contains an updated graphic schedule.
- **Missing Knowledge**: The `GraphicInputPackage` exposes a raw structural `ScheduleData` property, while the `Publication` exposes a `ScheduleHash`. It is undefined how the Situation Model mathematically hashes or maps `ScheduleData` to accurately compare it against `ScheduleHash`.

### 3. Steady-State Correlation (S-13)
The Situation Model must detect when no changes have occurred ("Edition already reflects current reality").
- **Missing Knowledge**: `EDITORIAL_INPUT_PACKAGE_MODEL.md` indicates S-13 relies on `PackageId` (and `GenerationTimestamp`), but the `Publication` internal representation does not store `PackageId`. It only stores a `ContentHash`. It is undefined how the Situation Model correlates the incoming `PackageId` with the `Publication` state, or whether `ContentHash` completely overrides the need for `PackageId` tracking.

## Decision Required
Implementation is blocked. Engineering decisions are required to define the strict mathematical and equality semantics for these comparisons. No architecture can be invented in the implementation repository without these rules.
